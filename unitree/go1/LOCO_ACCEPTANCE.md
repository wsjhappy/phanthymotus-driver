# Go1 loco 有反馈运动控制卡（本地开发版）

日期：2026-09-24。分支：`feat/go1-loco-confirmed`。

**状态：本地实现及离线测试完成；未部署，未完成 ARM64 镜像构建及真机验收。不能声明停止故障已修复。**

## 目的与边界

完善现有 `loco`，而不是另建重复的运动卡。面向室内短距离调整位置、转向、站起及中断运动，让调用方区分“请求已接受”和“已观察到动作结果”。

已确认的旧代码问题：限时运动启动线程即返回成功；后台异常没有关联最终结果；代理丢失异常及 RPC 超时，迟到回复没有请求 ID；平台中断使用的 `stop_move` 不在原卡动作接口中；停止没有实测速度确认。**这些是代码缺口，不等于已证明此前真机未动作或停止困难的唯一原因。** 固件状态、其他控制源和网络仍需排查。

不提供导航、精确位移控制、避障或硬件急停。不自动重试运动，不自动用趴下、阻尼、恢复站立代替停止。遥测观察不能证明运动必然由本命令引起，也不能代替现场观察。

## 功能与返回契约

| 功能 | 实现及判定 |
| --- | --- |
| 限时运动 `move` | 前后、横移、偏航可组合；每个指定轴均须观测到同向速度；到时请求停止并检查停稳。不延长动作补偿响应延迟。 |
| 停止 `stop` / `stop_move` | 同义入口；先触发独立进程共享停止信号、使旧命令代次失效，再等待停止反馈。 |
| 姿态动作 | 保留站起、趴下、平衡站立、恢复站立、阻尼；以新鲜模式、机身高度、姿态及速度按动作分别确认。后两者须显式 `confirm=true`。 |
| 状态 `status` | 按 `action_id`（也可传同步结果的 `command_id`）查询；省略则查当前/最近动作。保留最近 32 条，进程重启后不保留。 |
| 异步完成 | 长运动及姿态动作返回 `action_id`，通过 ACP 回报最终结果；回报失败记录到状态中，不盲目重复提交回调。 |
| 故障保护 | 参数、站立前置条件、遥测新鲜度、发送错误检查；同进程共享代理的动作所有权保护；异常/取消均请求停止。 |

- `accepted / ok=true / executed=false`：仅接收，**不是动作成功**。
- `completed / ok=true`：满足该动作的软件反馈判据；运动还必须满足停稳判据。不是精确速度/路程达标证明。
- `error / ok=false`：未执行、未确认或通信错误；`cancelled / ok=false`：被停止中断。
- `STOP_UNCONFIRMED`：不能确认已停，须遥控器接管并现场检查；不是必然仍在运动。原始故障保留在 `cause_code`。
- 停稳判据：停止请求后的至少 3 个不同收包序号，持续至少 0.15 秒满足平面速度 ≤0.03 m/s、偏航速度 ≤0.08 rad/s；默认等待 3 秒。**这些是待真机标定的开发阈值。**
- 遥测必须有递增 SDK 收包计数，且年龄 ≤0.5 秒；重复读取旧缓存不算新反馈。

停止信号绕过普通 RPC 查询锁；SDK 循环持续发送 `mode=0`、零速度中性命令并清除旧运动/姿态目标。它仍依赖 SDK 进程和 UDP 循环正常运行，**不保证物理急停**。本次尚未验证 `mode=0` 在该真机各模式下的停止效果。

## 兼容性与集成注意事项

- 保持卡名 `loco`，原动作保留，新增 `stop_move` 和 `status`。返回结构改为 `requested/observed/status`，不再把 `applied` 当作实际执行证明；旧调用方需按新契约适配。
- `vx` ±1 m/s、`vy` ±0.6 m/s（与底层一致）、`vyaw` ±90°/s；非零线速度绝对值至少 0.05 m/s，非零偏航至少 6°/s。小于阈值会拒绝，而非假装可以可靠确认。
- 省略 `duration` 或设 0 为 0.5 秒；默认最大 10 秒。≤2 秒同步，长运动及姿态动作异步。默认步态显式使用 1，实际发送与请求一致。
- 非停止动作正在执行时，新动作返回 `RESOURCE_BUSY`，不覆盖旧动作。停止信号锁存后，只有一次新的、通过前置检查的 `loco` 动作能解除。
- **影响其他控制卡：** `body_pose/gesture/switch_gait/special_motion` 等经共享代理写入时，遇到 loco 占用或停止锁存会被拒绝。未替其他卡补齐完成回报；旧脚本需适配，部署前须联调。该锁不能阻止另一台电脑、另一容器或遥控器控制。
- 已声明 `base` 资源及 `on_interrupt_motion/on_interrupt_all → stop_move`。平台普通工具调用可能被 ACP barrier 排队；紧急中断须走平台中断钩子或遥控器，不能依赖大模型口头“停止”。平台端钩子链路尚待联调。
- 必须重编译原生 `robot_interface`，新增只读 `UDP.udpState`。Docker 构建失败不再被忽略，构建时检查该属性。旧绑定缺少计数会拒绝动作，不会伪造新鲜数据。
- 已核对仓库 ARM64 SDK 二进制：`SetSend` 成功返回 0，`Send` 返回发送字节数；实现区分缓冲成功、实际发送正字节和断连/错误。

## 已执行的离线测试

运行：`python3 -m unittest -q tests.test_go1_loco_control tests.test_go1_motion_feedback`。

43 项通过（31 项新增控制/代理/SDK/注册测试，12 项原有反馈卡回归）。覆盖正常动作、没有运动、方向相反、部分轴执行、发送异常、过期遥测、重复包、停止不生效模拟、别名与中断声明、停止取消及旧命令失效、参数/前置检查、姿态确认/超时、ACP 成功与失败、RPC 错配/超时、共享锁及步态与看门狗。

这些测试使用假遥测，不证明实机移动、制动距离、可靠性或响应时延。当前电脑无 Docker，未做镜像构建；本轮没有向机器人发送指令。

## 真机验收计划（未执行）

1. 开机后先核对正在运行的版本、唯一 UDP 控制进程、SDK 新绑定和实际收包计数。遥测静止时计数应增长，断流时年龄应增长；先做不运动检查。
2. Master 在场、遥控器在手、平整空旷区域、网线有余量且没有其他主动控制源。先静止调用两个停止入口，分别记录请求、返回与现场观察。
3. 仅在允许的空间内，先测试 `vx=0.1, duration=0.5` 的单次小范围动作；确认方向、限时、到时停稳。不默认执行长距离或复合动作。
4. 现场明确允许后，在另一独立调用通道中途触发平台中断，检查旧动作返回 cancelled、不重新启动；记录实测停止时延/距离。**出现停止未确认、遥控器控制异常或异常运动，立即由现场人员接管，终止测试。**
5. 逐项验证姿态反馈与平台 ACP/画布链路；高风险恢复、阻尼动作单独审批，不纳入自动测试。故障注入首先在离线环境完成，不能为测试而在真机运动中故意切断安全控制。
6. 每项保存代码 SHA、镜像标识、参数、请求/回包时间、收包序号、速度曲线、最终结果及现场录像。停止路径和平台联调未通过前，不作为已验收卡片提交。
