# Go1 新卡 loco_confirmed：设计与验收说明

日期：2026-09-24。分支：`feat/go1-loco-confirmed-card`。
状态：开发中；离线测试通过，未部署、未做新卡真机运动验收。不能宣称停止故障已修复。

## 设计目的

在保留原 `loco` 卡的前提下，新增独立卡片 `loco_confirmed`。用于短距离调整位置、转向及动作中断，让调用方区分“请求已接收”和“观察到动作结果”。

`controllers.py` 与主仓库版本一致，原卡名、动作和返回结构不变。新增卡在同一 bundle 中注册，复用唯一 SDK/UDP 客户端；不能再起一个直接连接运动服务的并行容器。

旧代码存在异步接受后没有最终结果、RPC 错误丢失、停止未确认等缺口。这些代码问题不等于已证明历史运动失败的唯一原因。2026-09-24 最近一次遥测断流的日志另显示启动时网络不可达，重启原驱动后恢复；不要将它误归因于动作返回逻辑。

## 功能

- 有限时前后、横移、偏航；组合命令要求各个指定轴出现同向反馈，到时请求停止，不自动延长或重试运动。
- `stop/stop_move` 两个停止入口；独立共享停止信号、旧命令代次失效、持续中性命令及新鲜遥测停稳检查。
- 站起、趴下、平衡站立、恢复站立、阻尼。后两项要求显式 `confirm=true`，不作为自动停止兜底。
- `status` 查询当前或最近动作，支持按 action_id/command_id 查询，保留最近 32 条；重启不保留。
- 长动作以 ACP 回报 completed/error/cancelled；回调失败保留到状态中，不盲目重发。
- 检查参数、站立状态、收包新鲜度及发送错误；新卡不能抢占原卡正在进行的移动。

## 安全开关与兼容性

默认配置为 `plugins.loco_confirmed.enabled=true`、`control_enabled=false`：卡片可列出、可查状态，但所有控制动作返回 CONTROL_DISABLED，也不注册中断钩子。新卡生命周期不会在这个模式下向原 SDK 发停止命令。

仅在现场确认安全并通过 Master 验收安排后，显式开启 control_enabled 并重新加载服务。不得将“成功注册卡片”当作“运动验收通过”。

共享底层 SDK/代理有必要改动：请求 ID、异常传播、停止代次、收包计数绑定。**原卡实现不替换，不代表底层行为完全不变。** 新卡启用并执行时，同代理的其他控制卡写入会被拒绝；新卡停止锁存后，需通过新的新卡动作解除。禁止新旧两套控制同时驱动机器人，旧卡停止/脚本及姿态卡的兼容性需专项联调。这不能阻止其他电脑或遥控器抢占控制。

原卡的既有返回语义保持不变；本 PR 不声称修复所有旧卡。机器人当前温度卡来自另一个开发分支，正式部署必须在保留那个分支的代码基础上增量整合，不能直接用本分支镜像覆盖。原镜像、原容器配置和温度卡文件须留作回滚。

## 返回与判据

- accepted / ok=true / executed=false：只表示接收，不表示动作成功。
- completed / ok=true：符合软件反馈判据；move 还需停稳确认。不是精确距离、精确速度或运动因果的证明。
- error / ok=false：失败或无法确认；cancelled / ok=false：停止中断。
- STOP_UNCONFIRMED：无法证明停稳，须遥控器接管；不代表必然仍在运动。原始故障保留在 cause_code。

遥测年龄须 ≤0.5 秒且存在新收包序号；重复读取缓存不算新样本。停稳要求停止请求后至少 3 个不同样本，持续 ≥0.15 秒满足平面速度 ≤0.03 m/s、偏航 ≤0.08 rad/s，默认等待 3 秒。阈值待真机标定。

速度范围：vx ±1 m/s、vy ±0.6 m/s、vyaw ±90°/s；非零线速度至少 0.05 m/s，非零偏航至少 6°/s。duration 省略或 0 为 0.5 秒，默认上限 10 秒；≤2 秒同步，长移动和姿态动作异步。

停止仍是依赖运行中的 SDK/UDP 的软件请求（mode=0、零速度），不保证硬件急停。网络故障、进程卡死或外部控制源都可能使它失效。普通平台工具调用可能排在 ACP barrier 后；启用新卡后使用其明确声明的中断钩子，紧急情况依靠遥控器。

## 当前部署阻碍及验收顺序

检查时 Go1 根分区使用率 99%，仅余约 449 MB，不适合直接构建新镜像。现有温度卡和画布服务保留运行；未清理镜像、未停止原服务、未启动新控制客户端。

1. 明确可回收的具体文件/镜像并取得清理许可，或使用经批准的外部存储/构建环境。不能做无范围的 docker prune。
2. 备份现有容器参数、原镜像及温度卡源文件。在独立构建目录增量集成新卡与必要共享 SDK 修改，不修改原仓库分支。native robot_interface 必须重编译以暴露 udpState。
3. 维护窗口内加载包含新旧卡的单一 SDK bundle；原卡和温度卡保留。不能以不同端口再起一套 SDK 并行抢占运动服务。
4. 先以 control_enabled=false 验证画布同时列出原 loco 与 loco_confirmed，旧传感器、温度卡持续更新，新卡控制请求被拒绝。
5. 平整空旷区域、遥控器在手、有人看护、网线有余量、无其他主动控制源。确认后开启新卡，先静止停止测试，再由现场授权执行单次 vx=0.1、duration=0.5 的小范围动作；高风险姿态单独审批。
6. 保存代码 SHA、镜像版本、调用结果、收包与速度时间序列、停止时延/距离和现场录像。新卡、旧卡兼容与平台中断链路全部通过后才申请验收合并。
